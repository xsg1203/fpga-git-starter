# 上板调试记录 · M2（采集直显）

> 阶段：M2 采集链路验证
> 目标：VGA 上出现 OV5640 实时画面
> 状态：⏳ 待上板

> **历史修复记录（三次，都会导致黑屏/无图，且都不报错）**
>
> 1. **2026-11-21 上午**：`i2c_sccb.v` 用的是 OV7670 的 3 字节写格式。OV5640 的寄存器
>    地址是 16 位，必须 `78 + 地址高 + 地址低 + 数据`。原写法下寄存器从未被写入，
>    而器件地址照回 ACK，所以 LED3 不报错 —— **灯全对、屏幕全黑**。
> 2. **2026-11-21 晚**：`ov5640_cfg.v` 的寄存器表本身有错。输出窗口拆字节错位
>    （X end 写成 2723 越界、Y end 写成 10 比 Y start 只大 6 行），且 `0x3C07~0x3C0D`
>    被写入 0x07 把曝光上限压到最小。前者让 ISP 不产生有效帧，后者让图像近似全黑
>    但行场同步正常 —— 两种都表现为黑屏。
> 3. **2026-11-21 22:00（本项目最坑的一次）**：上一轮修复时把 `0x3017/0x3018` 从
>    `0xFF/0xF0` 改成了 `0x00/0x00`，理由写成"DVP 必须关掉 MIPI pad"——**方向理解反了**。
>    数据手册 table 2-2 明确：这两个寄存器是 **PAD 方向控制，0 = 输入，1 = 输出**。
>    写成 0x00 等于让传感器把 VSYNC/HREF/PCLK/D[9:0] 全部当**输入**，它一条线都不驱动。
>    现象是：**屏幕 8 色竖条 + LED1 亮 + LED2 也亮**。LED2 亮极具迷惑性——那是 K17
>    悬空后采到的噪声边沿，让人误以为"有同步但没像素"。正确值：`0x3017=0xFF`、
>    `0x3018=0xFC`（8bit DVP 只用 D[9:2]，0xFC 只开 D[5:0]，GPIO 保持输入）。
>
> **教训（已固化为自动检查）**：`sim/tb_ov5640_cfg.v` 原来只检查"条数/首尾"，
> 值写反了照样 PASS。现在改为按地址建表逐条核对关键值（pad 方向、窗口、格式、
> 曝光上限），值错会直接 FAIL。**改寄存器表后必须先跑这个 TB，再看时序报告。**
>
> **结论：不要再沿用旧位流。** 现在 `ct_top` 内置了"无图自动切 FPGA 彩条"，
> 黑屏这个现象已经被消除，看到什么就直接对应到下表的状态。

---

## 1. 上电顺序

1. 断电插好扩展板、OV5640 模块、VGA 线。
2. 确认电源极性与电压（VCC_IN 5V），**反接会烧核心板**。
3. 上电，接 JTAG，Program Device 下载 `build_flat/ct_top.bit`。
4. 按下表读 LED，再看屏幕。

## 2. 三种画面状态（核心判据）

`ct_top` 会统计"这一帧有没有写进非零像素"。连续 1 秒没有，就把画面切成
FPGA 内部 8 色竖条（白/黄/青/绿/品红/红/蓝/黑）；一旦摄像头出图，立即切回实时画面。

| 屏幕内容        | LED2 | LED1 | 含义                     | 问题在哪          |
| ----------- | ---- | ---- | ---------------------- | ------------- |
| **摄像头实时画面** | 亮    | 亮    | 采集 + 缓存 + 显示全通          | 无，M2 可签核     |
| **8 色竖条**   | **灭** | 亮    | 显示通路正常，但**完全没有 VSYNC** | 摄像头侧：XCLK/供电/复位/SCCB 配置失败 |
| **8 色竖条**   | **亮** | 亮    | 有 VSYNC，但像素全为 0         | 窗口/格式/曝光配置错（§5） |
| 纯黑 + 显示器"无信号" | —    | —    | VGA 时序或 RGB 线序问题        | 先查 VGA 排线，再查 hsync/vsync 极性 |
| 纯黑          | 灭    | 灭    | SCCB 卡住，序列没走完          | 查 SCL/SDA 上拉与接线 |
| 纯黑          | 灭    | 亮    | MMCM 未锁定                | 时钟/约束问题，看 implement 报告 |

> **为什么加了彩条**：原来黑屏至少对应四种互斥原因（没 VSYNC / 有 VSYNC 但全黑 /
> 显示坏了 / 传感器没配置），肉眼无法区分，只能靠示波器和 ILA 一个个试。
> 彩条把"显示通路"从变量里摘出去，剩下的都归到摄像头侧，一次上电就能定方向。
>
> ⚠️ **LED2 不能当作"摄像头正常"的证据**。如果传感器把 DVP 引脚设成了输入
> （`0x3017/0x3018` 写错，见开头第 3 条），K17 悬空，噪声边沿照样能把 `vs_seen`
> 置起来、LED2 照样亮。所以 LED2 亮只代表"PCLK 上有边沿"，**不代表能出像素**。
> 真正可信的是屏幕：出画面才算通。

## 3. 其余屏幕现象速查

| 现象              | 最可能原因                        | 处置                                              |
| --------------- | ---------------------------- | ----------------------------------------------- |
| 画面能出但整体偏色       | RGB565 字节序反了                 | 把 `ov5640_capture.v` 里 `{b1,data}` 改 `{data,b1}` |
| 画面上下/左右反了       | 镜像位不对                        | 改 `0x3820 / 0x3821`（当前 0x41 / 0x07）             |
| 画面斜条纹/错位        | PCLK 采样相位不对                  | 改 `0x3035/0x3036` 降低 PCLK，或改为 PCLK 下降沿采样         |
| 画面正常但有一条横向撕裂线   | 单缓冲帧边界（已知，方案 A1 接受）          | 无需处理                                            |
| 画面比例变形          | 摄像头窗口不是 4:3                  | 核对 `0x3808~0x380B` = 640×480                    |

## 4. 分步定位（当屏幕显示 8 色竖条时）

### 4.1 SCCB 是否通

- 用示波器看 `J18(SCL)`：每写一个寄存器是 **4 字节 × 9 拍 = 36 个时钟**，
  帧间约 40us 间隔，共 95 帧。
- 看 `G20(SDA)`：SCL 低期间变化；第 9/18/27/36 个时钟应被从机拉低（ACK）。
- LED3 亮 = 出现无 ACK：先量 SDA/SCL 静态电平，**空闲都应为 3.3V**。
  为 0V 或悬空 → 检查模块板上 4.7K 上拉是否装配。

### 4.2 摄像头是否在出时钟

| 测点        | 期望          | 没有时的含义              |
| --------- | ----------- | ------------------- |
| `F20` XCLK | **24MHz** 方波 | 引脚/位流问题（MMCM CLKOUT2） |
| `E19` PCLK | 约 **56MHz** 方波 | 配置没生效，回到 4.1        |
| `K17` VSYNC | 约 30Hz 正脉冲  | 有 PCLK 无 VSYNC → 窗口/VTS 配置 |

> 三个测点必须**都实测**，不能靠 LED 推断。2026-11-21 那次事故里，`0x3017/0x3018`
> 把引脚全设成输入，传感器一条线都没驱动，但 K17 悬空噪声让 LED2 亮了，
> 于是被误判成"有同步无像素"，多花了一轮排查。

> XCLK 从原来的 25MHz 改成 **24MHz**：硬件说明标注 24MHz，且表里 `0x3036=0x69`
> 的倍频值就是按 24MHz 标定的，差 4% 会让 PCLK 与帧率同步偏 4%。
> PCLK 由 `HTS(1896) × VTS(984) × 30fps ≈ 56MHz` 推得，不是猜的。

### 4.3 打开传感器内部自测图案（二分法）

把 `rtl/ov5640/ov5640_cfg.v` 第 `9'd90` 条改成 `0x82`：

```verilog
9'd90 : cfg_rom = {16'h503D, 8'h82};   // 0x82 = 传感器内部彩条
```

重新综合下载：

- **传感器彩条能出** ⇒ 采集/缓存/VGA 链路全通，问题只在镜头、曝光或窗口参数。
- **传感器彩条也不出，但 FPGA 彩条正常** ⇒ 问题在传感器配置或 DVP 数据线，与显示无关。

这一步和 FPGA 内部彩条是两条独立的二分线，配合用能把问题锁到单个模块。

## 5. 现场需核对的寄存器（当前表已被验证为合法的值）

| 寄存器           | 当前值           | 作用          | 不对时的现象        |
| ------------- | ------------- | ----------- | ------------- |
| **0x3017**    | **0xFF**      | **PAD 方向：[6]VSYNC [5]HREF [4]PCLK [3:0]D[9:6]，1=输出** | **写 0x00 → 传感器不驱动任何线，彩条+假同步** |
| **0x3018**    | **0xFC**      | **PAD 方向：[7:2]D[5:0]，1=输出** | **同上** |
| 0x3804/0x3805 | 0x0A / 0x3F   | X end = 2623 | 越界 → ISP 不出帧、全黑 |
| 0x3806/0x3807 | 0x07 / 0xA3   | Y end = 1955 | 同上            |
| 0x3808~0x380B | 0x02/0x80/0x01/0xE0 | 输出 640×480 | 分辨率/比例错 |
| 0x380E/0x380F | 0x03 / 0xD8   | VTS = 984（30fps） | 帧率不对     |
| 0x4300        | 0x6F          | RGB565 输出   | 偏色 / 像 YUV    |
| 0x3035/0x3036 | 0x11 / 0x69   | PLL（24MHz 标定，0x11 = 不降频） | PCLK 频率不对，斜纹 |
| 0x3820/0x3821 | 0x41 / 0x07   | 镜像翻转        | 画面反 / 异常条带   |
| 0x3C04/0x3C05 | 0x28 / 0x98   | AEC 曝光上限    | 上限过小 → 全黑但有同步 |
| 0x503D        | 0x00          | 测试图案        | 0x82 = 传感器彩条   |

> 若以上都调不通，可直接替换成你手上模组厂商给的完整初始化表：
> 只改 `cfg_rom` 的 case 内容，`{ADDR[15:0], DATA[7:0]}` 的 24 位格式不变，
> 序列器与 SCCB 都不用动。改完请跑 `sim/tb_ov5640_cfg.v` —— 它会按地址逐条
> 核对上表这些关键值，**值写错会 FAIL，不会再出现"结构对了但功能不对"的情况**。

## 6. 构建期报错速查

### 6.1 `module 'xxx' not found` —— 不是代码错，是文件没登记

```
ERROR: [Synth 8-439] module 'sccb_rd' not found [rtl/ct_top.v:174]
```

`.xpr` 里的文件列表是**建工程那一刻的快照**，之后往 `rtl/` 里加模块它不会自动知道。
判断方法：打开 `.xpr` 所在目录的 `synth_1/runme.log`，如果错误只有这一条、
被调用的模块文件确实存在，就是 fileset 过期。

修复（不用关 Vivado，在 GUI 的 Tcl Console 里执行）：

```tcl
source {D:/fpga/color_track_ebaz4205/scripts/refresh_fileset.tcl}
```

它会递归扫描 `rtl/`、补上缺失文件、更新编译顺序、复位 `synth_1`/`impl_1`，
最后打印 `==== REFRESH OK ====` 和工程内 RTL 总数。

> **为什么容易被误判**：`build_flat.tcl` 直接读源码、不经过 `.xpr`，
> 所以它能跑通、位流也能出来。于是「批处理能出比特流、GUI 一点综合就报错」
> 同时成立 —— 这个组合基本可以断定是 fileset 不同步，而不是 RTL 有问题。

### 6.2 `requires 18 connections, but only 17 given`

`MMCME2_BASE` 有 18 个端口，漏接的是 `CLKOUT6`（不是 `CLKINSEL`——
那是 `MMCME2_ADV` 才有的端口，加到 `MMCME2_BASE` 上会直接报
`named port connection 'CLKINSEL' does not exist`）。
